# Відомі обмеження, технічний борг і ризики

Код створювався ітеративно з AI-асистентом і не проходив автоматичної перевірки; нижче те, що відомо з аналізу коду й тестового використання.

## Дефекти і обмеження

| # | Опис | Вплив |
|---|---|---|
| L-01 | Дані не зберігаються: запис і налаштування зникають після закриття додатка | Високий |
| L-02 | Параметри EQ, компресора, delay, reverb змінюються лише AI-командами; слайдерів немає | Середній |
| L-03 | `Ai.apply` не обмежує значення діапазонами; `feedback ≥ 1` дає наростання звуку | Середній |
| L-04 | Для `compressor` та `eq` пропущені числові поля скидаються до значень за замовчуванням, а не залишаються поточними; `eq` без поля `on` вмикається, хоча інші ефекти зберігають поточний стан | Низький |
| L-05 | Лише mono; лише розмір сітки 4/4; частота дискретизації фіксована 44.1 кГц | Низький |
| L-06 | Осцилограф у режимі Recording перехоплює жести: прокрутка сторінки не починається з пальця на ньому | Низький |
| L-07 | Під час запису з динаміка виникає фідбек, якщо одночасно грає звук | Низький |
| L-08 | `Eq.set`, `Delay.fb/mix` змінюються з UI-потоку без синхронізації; можливі короткі артефакти | Низький |
| L-09 | Запис нормалізується до 0.9, оригінальний рівень не зберігається | Низький |
| L-10 | Весь запис лежить у пам'яті; довгі записи (десятки хвилин) можуть вичерпати пам'ять | Середній |
| L-11 | Мінімальна відстань між маркерами 64 семпли; зум обмежений 32 семплами | Інформаційно |
| L-12 | Слайдер BPM має діапазон 60-200, тоді як AI може задати 40-240; значення поза слайдером відображається некоректно | Низький |
| L-13 | `Engine` створюється в `Activity`: поворот екрана або інша зміна конфігурації створює новий `Engine` і скидає запис, курсор, маркери та налаштування | Середній |

## Технічний борг

- DSP і аудіовихід на Kotlin: можливі паузи збирача сміття та більша затримка, ніж у C++/Oboe (R-25).
- Немає тестів, CI та перевірки форматування.
- Весь UI в одному файлі `MainActivity.kt`; `ScopePanel` потребує розбиття на менші компоненти.
- Немає `ViewModel`: стан живе в `remember` і зникає при зміні конфігурації (поворот екрана).
- `Engine` створюється в `Activity`; потрібне виділення в сервіс чи DI для роботи у фоні.
- Назва моделі Gemini і версії залежностей Firebase заходять із документації на момент написання й потребують перевірки.
- Рішення про `minSdk` не зафіксоване (спочатку заявлено Android 17+, в `decisions.md` рекомендовано нижчий поріг); перевірити в `app/build.gradle.kts`.

## Ризики

| Ризик | Заходи |
|---|---|
| Витік ключів (вже траплявся сигнал GitHub про Google API key) | `google-services.json` в `.gitignore`, обмеження ключа пакетом і SHA-1, App Check, Push protection на GitHub |
| Витрати на хмарний AI | бюджетні сповіщення, App Check, ліміти запитів, правила як перший рівень |
| Висока затримка звуку на деяких пристроях | тест на реальних пристроях, перехід на Oboe |
| Неправильні значення від AI ламають звук | валідація діапазонів у `Ai.apply` (R-28) |
| Мікрофон недоступний (емулятор, дозволи) | явні повідомлення в UI (вже є), тест на реальному пристрої |
