# Відомі обмеження, технічний борг і ризики

Код створювався ітеративно з AI-асистентом і не проходив автоматичної перевірки; нижче те, що відомо з аналізу коду й тестового використання.

## Дефекти і обмеження

| # | Опис | Вплив |
|---|---|---|
| L-01 | Незбережений запис і налаштування зникають після закриття додатка; зберігається лише те, що натиснуто Save | Середній |
| L-02 | Параметри EQ, компресора, delay, reverb змінюються лише AI-командами; слайдерів немає | Середній |
| L-03 | `Ai.apply` не обмежує значення діапазонами; `feedback ≥ 1` дає наростання звуку | Середній |
| L-04 | Для `compressor` та `eq` пропущені числові поля скидаються до значень за замовчуванням, а не залишаються поточними; `eq` без поля `on` вмикається, хоча інші ефекти зберігають поточний стан | Низький |
| L-05 | Лише mono; лише розмір сітки 4/4; частота дискретизації фіксована 44.1 кГц | Низький |
| L-06 | Осцилограф у режимі Recording перехоплює жести: прокрутка сторінки не починається з пальця на ньому | Низький |
| L-07 | Під час запису з динаміка виникає фідбек, якщо одночасно грає звук | Низький |
| L-08 | `Eq.set`, `Delay.fb/mix` змінюються з UI-потоку без синхронізації; можливі короткі артефакти | Низький |
| L-09 | Запис нормалізується до 0.9, оригінальний рівень не зберігається | Низький |
| L-10 | Весь запис лежить у пам'яті; довгі записи (десятки хвилин) можуть вичерпати пам'ять | Середній |
| L-11 | Мінімальна відстань між маркерами 64 семпли; зум обмежений 32 семплами | Інформаційно |
| L-12 | Виправлено: BPM вводиться числом у діапазоні 40–240, як і в AI (раніше повзунок 60–200 не показував значення від AI поза ним). Зміна BPM тепер одразу перераховує час delay | Інформаційно |
| L-13 | `Engine` створюється в `Activity`: зміна конфігурації створює новий `Engine` і скидає запис, курсор, маркери та налаштування. **Лаба 7:** орієнтацію зафіксовано (`screenOrientation="portrait"` у маніфесті), тому поворот екрана більше не перестворює `Activity`. На великих екранах (планшет, розкладний телефон, ширина ≥ 600 dp) Android 16+ ігнорує фіксовану орієнтацію для застосунків з `targetSdk` ≥ 36 (у нас 37), тож там поворот і далі скидає стан; перевірки проводяться на телефоні. Інші зміни конфігурації (перемикання темної теми, мови, розміру шрифту, режим multi-window) і далі скидають стан. Повне рішення — перенести `Engine` у `AppContainer` | Низький |
| L-14 | Кожен Save створює новий запис: перезапису й перейменування немає | Низький |
| L-15 | Зберігається сухий запис і параметри ефектів, а не оброблений звук; експорт результату запланований (R-24) | Інформаційно |
| L-16 | Запис у WAV 16 біт: невелика втрата точності порівняно з float у памʼяті | Інформаційно |
| L-17 | Room: версія схеми 1, `exportSchema=false`, міграцій немає; зміна схеми потребує міграції або очищення даних | Середній |
| L-18 | Файли лежать у приватній папці додатка: зникають разом з додатком; за ввімкненого Auto Backup можуть потрапити в хмарну копію Google (перевірити `allowBackup` у маніфесті) | Низький |
| L-19 | Нестача місця чи збій запису повертає повідомлення в рядку статусу, але повторної спроби чи очищення старих записів немає | Низький |
| L-20 | WAV зберігається як stereo, але канали ідентичні (mono-сигнал у L і R); при завантаженні stereo зводиться назад у mono; справжнього стерео, панорами та стерео-ефектів немає (див. L-05) | Інформаційно |
| L-21 | Під час переходу між вкладками Studio/AI/Library `ScopePanel` перестворюється: масштаб і зсув перегляду та View gain скидаються (курсор і loop-маркери зберігаються через `ViewState`) | Низький |
| L-22 | `RunAiCommandUseCase` повертає `Result<AiReply>`, а категорія помилки дістається приведенням `exceptionOrNull() as AiException`; типобезпечнішого результату (sealed) немає | Інформаційно |
| L-23 | ViewModel переживає зміну конфігурації, а Engine створюється в Activity (L-13): якщо конфігурація змінилась під час запиту, результат буде застосовано колбеком до вже зупиненого рушія. Після фіксації орієнтації (Лаба 7) поворот цього не викликає; лишаються інші зміни конфігурації (L-13) | Низький |
| L-24 | Retry пам'ятає лише один останній невдалий запит і лише в межах життя `ViewModel`; після завершення процесу він губиться. Запит `InvalidInput` не повторюється | Інформаційно |
| L-25 | Збій хмари, який `HybridSource` ховає за відповіддю правил (`rules (cloud failed)`), показується як `Success` («No actions recognized»), тому Retry для нього не пропонується | Низький |
| L-26 | Попередження компілятора не виправлялися, щоб не змішувати з рефакторингом: `TabRow` застарілий (є `PrimaryTabRow`), `delay(Long)` замість `Duration`, `mutableStateOf(Float)` замість `mutableFloatStateOf` | Інформаційно |
| L-27 | AI-чат: модель недетермінована; на `make sound warmer` приблизно 1 з 3–4 відповідей — EQ увімкнено без значень. Застосунок показує «нічого не змінено», а не ✓, але користувачу треба повторити запит | Низький |
| L-28 | Текст `reply`/`why` від моделі може не збігатися з фактичною дією (E2: «reducing the highs», а змінено mid). Блок Changed завжди фактичний (рахується на пристрої), текст моделі — ні | Низький |
| L-29 | Повідомлення чату і контекст для моделі (3 останні репліки) живуть лише у `ViewModel` і зникають після закриття застосунку; в AI history (Room) пишеться лише запит, JSON і текст відповіді | Інформаційно |
| L-30 | **Виправлено (Лаба 7, BUG-02):** при delay 1/4 «зроби delay довшим» давало 1/4 → 1/8, а на `f2e7585` — 1/4 → 1/16. Причина — неоднозначне «smaller division» в `Ai.SYSTEM`; переписано (4 = LONGEST, 16 = SHORTEST, на межі без дії). Повторна перевірка 4/4 — «вже найдовший». Модель недетермінована: гарантії немає, але «що змінено» завжди рахується на пристрої | Середній |
| L-31 | Безкоштовна модель Gemini буває перевантажена («high demand», таймаути; 23.11.2026 відповіді до 3 хв). Таймаут 20 с і Retry обробляють це, але функція в такі моменти недоступна | Низький |
| L-32 | Виправлено: перетягування loop-маркера біля краю екрана запускало системний жест «Назад» і застосунок закривався. Осцилограф тепер виключено з жестів країв (`systemGestureExclusion`); Android дозволяє це лише на 200 dp висоти біля кожного краю, тому висоту осцилографа (200 dp) не можна збільшувати без втрати цього захисту | Інформаційно |
| L-33 | Модель іноді повертає дію без значень (`{"fx":"bpm","why":…}`) і пише в `reply`, ніби зміну зроблено («Я встановив темп на 240»), хоча нічого не змінено. Правило в `Ai.SYSTEM` проти цього модель не виконує (3/3). Застосунок показує факт першим — «Nothing changed: the AI reply had no values…» — а текст моделі лише як цитату «AI said: …» (BUG-06). Числовий темп обробляється правилами (BUG-04), тому випадок лишається для формулювань словами | Низький |
| L-35 | Мова відповіді моделі: після уточнення `Ai.SYSTEM` (BUG-03) відповіді переважно мовою запиту, але трапляються англійські (FT-01, 26.11.2026 05:22: «Reverb mix is already at 13%…» на український запит). Модель недетермінована; детермінований захист не реалізовано | Низький |
| L-36 | Повторний той самий відносний запит модель може трактувати як уже виконаний через історію чату («already at 13%, close to half of the previous reduction») і нічого не змінити. Застосунок показує це чесно (нічого не змінено) | Низький |
| L-37 | `responseSchema` пласка: будь-яке поле дозволене в будь-якій дії, тож модель може надіслати `threshold`/`value` для reverb; такі поля мовчки ігноруються `AiActionMapper` (FT-05). Сувора схема з окремим об'єктом на кожен ефект не реалізована | Низький |
| L-34 | Debug token App Check прив'язаний до встановлення: після перевстановлення, очищення даних або на новому пристрої хмарний AI недоступний (`403 App attestation failed` → «Cloud AI is unavailable…»), доки новий token з Logcat (`DebugAppCheckProvider`) не додано в Firebase Console. Застосунок обробляє це без падіння (FT-04). Release-збірка без Play Integrity App Check не пройде — для демонстрації лише debug APK | Середній |

## Технічний борг

- DSP і аудіовихід на Kotlin: можливі паузи збирача сміття та більша затримка, ніж у C++/Oboe (R-25).
- Немає тестів, CI та перевірки форматування.
- Весь UI в одному файлі `MainActivity.kt`; `ScopePanel` потребує розбиття на менші компоненти.
- Немає `ViewModel`: стан живе в `remember` і зникає при зміні конфігурації (поворот екрана).
- `Engine` створюється в `Activity`; потрібне виділення в сервіс чи DI для роботи у фоні.
- Назва моделі Gemini і версії залежностей Firebase заходять із документації на момент написання й потребують перевірки.
- Рішення про `minSdk` не зафіксоване (спочатку заявлено Android 17+, в `decisions.md` рекомендовано нижчий поріг); перевірити в `app/build.gradle.kts`.

## Ризики

| Ризик | Заходи |
|---|---|
| Витік ключів (вже траплявся сигнал GitHub про Google API key) | `google-services.json` в `.gitignore`, обмеження ключа пакетом і SHA-1, App Check, Push protection на GitHub |
| Витрати на хмарний AI | бюджетні сповіщення, App Check, ліміти запитів, правила як перший рівень |
| Висока затримка звуку на деяких пристроях | тест на реальних пристроях, перехід на Oboe |
| Неправильні значення від AI ламають звук | валідація діапазонів у `Ai.apply` (R-28) |
| Мікрофон недоступний (емулятор, дозволи) | явні повідомлення в UI (вже є), тест на реальному пристрої |
