# AI-компонент

## Призначення

Перетворити текстову команду користувача на список дій над параметрами додатка. AI **не обробляє і не генерує звук**: він лише повертає JSON, а `Ai.apply` виконує його тими ж сетерами, що й інтерфейс.

Приклад: «додай delay 1/8 в темпі 120 BPM, включи компресор» → `bpm=120`, `delay.on=true`, `delay.denom=8`, `comp.on=true`.

## Джерела команд (`CommandSource`)

| Реалізація | Опис | Потребує |
|---|---|---|
| `RulesSource` | шаблони на ключових словах (bpm, delay + `1/N`, compress, reverb); офлайн, миттєво | нічого |
| `FirebaseSource` | Gemini через Firebase AI Logic, `responseMimeType = application/json`, системна інструкція `Ai.SYSTEM`; модель за замовчуванням `gemini-3.5-flash` (назву треба звіряти з документацією Firebase) | Firebase налаштовано (`google-services.json`, плагін), мережа |
| `HybridSource` | за замовчуванням: спершу правила, якщо дій немає, то хмара | як вище |

Змінити джерело: `di/AppContainer.kt` (там збирається `HybridSource` і перемикач `useFake`). Інтерфейс `CommandSource` лежить у `ai/domain/CommandSource.kt`, реалізації в `ai/data/`.

## Обмеження

- Перелік доступних дій фіксований: `bpm`, `delay`, `reverb`, `compressor`, `eq`. Просити «зроби тепліше» без відповідної мапи на параметри поки не підтримано.
- Правила розуміють лише задані фрази (укр./англ. ключові слова); складні запити потребують хмари.
- Значення від моделі не валідуються за діапазонами (ризик нестабільного feedback, див. [known-limitations.md](known-limitations.md)).
- Немає історії діалогу: кожна команда незалежна, моделі не передається поточний стан додатка.
- Хмарна модель потребує мережі та налаштованого Firebase; тарифи й квоти треба перевіряти в документації Firebase.
- Для `compressor` та `eq` пропущені числові поля скидаються до значень за замовчуванням, а `eq` без `on` вмикається (точна таблиця: [api-contract.md](api-contract.md)).

## Fallback

1. Хмара недоступна, не налаштований Firebase або помилка → `HybridSource` повертає відповідь правил.
2. Правила нічого не розпізнали → порожній список дій, додаток не змінюється.
3. Некоректний JSON → виняток; UI ловить `Throwable` і показує повідомлення в блоці логу.
4. Помилка ініціалізації Firebase не валить додаток: модель створюється ліниво при першому хмарному виклику.

## Безпека

- Ключі API не зберігаються в коді. `google-services.json` не комітиться; ключі в Google Cloud обмежуються пакетом і SHA-1.
- App Check: у debug-збірці `di/AppCheckSetup.kt` (`app/src/debug`) ставить `DebugAppCheckProviderFactory`; debug-токен з Logcat (тег `DebugAppCheckProvider`) додається в консолі Firebase → App Check → Manage debug tokens. У release-збірці (`app/src/release`) провайдера поки немає, тому вмикати enforcement можна лише після додавання Play Integrity.
- Команди користувача виконують лише дозволені `fx`; довільний код чи доступ до файлів через AI неможливі.
