# Фінальний сценарій і критерії роботи системи (Лабораторна 7, Задача 1)

Пов'язані документи: [project-overview.md](project-overview.md) (користувач, MVP), [ai-chat.md](ai-chat.md) (AI-чат, Лаба 6),
[evaluation.md](evaluation.md) (контрольні приклади).

## 1. Сценарій

**Користувач** — музикант або звукоінженер-початківець, який записує ідею на телефон і хоче швидко обробити її
ефектами, не знаючи, які саме параметри крутити.

**Задача** — отримати потрібне звучання, описавши його звичайними словами, і зрозуміти, що саме змінилось.

> Користувач записує фрагмент з мікрофона (Record) або відкриває збережений запис, переходить у вкладку **AI** і пише
> запит любою мовою, наприклад `зменш reverb наполовину` або `make sound warmer`. Застосунок змінює параметри
> (BPM, delay, reverb, compressor, EQ) і відповідає в чаті: **що змінено** (було → стало) і **навіщо**.
> Далі користувач **слухає результат** (Play / Loop A-B) і **зберігає запис разом з ефектами** (Save) або пише
> наступний запит, щоб уточнити звучання.

| | |
|---|---|
| Вхідні дані | текст запиту (≤ 500 символів) + поточний стан ефектів і BPM; для прослуховування — запис з мікрофона або збережений |
| Обробка | прості однозначні команди — правила на пристрої (офлайн); решта — Gemini `gemini-3.5-flash-lite` через Firebase AI Logic |
| Очікуваний результат | параметри змінено в межах допустимих діапазонів; у чаті список змін «було → стало» (рахується на пристрої) і пояснення «навіщо» |
| Подальша дія (наявний функціонал) | Play / Loop A-B → Save (зберігає WAV + ефекти + BPM у Room) → пізніше Load зі списку збережених |

## 2. Критерії роботи системи

Кожен критерій перевіряється на емуляторі або телефоні приблизно за 2 хвилини.

| ID | Критерій | Як перевірити |
|---|---|---|
| K-1 | **Функціонал.** З мережею запит `зменш reverb наполовину` (reverb увімкнений) змінює reverb mix приблизно вдвічі (з дефолтних 25% до ≈ 13%); у відповіді кожен змінений параметр має рядок «було → стало» і пояснення; перемикачі ефектів на Studio відповідають відповіді | Studio: увімкнути Reverb → вкладка AI → надіслати запит → рядок Changed `Mix: 25% → 13%`; Studio: перемикач Reverb лишився увімкненим. (Слайдерів mix на Studio немає — значення видно лише в чаті й у Logcat `AiChat`) |
| K-2 | **Час.** Прості команди (`120 bpm`, `reverb off`, `delay 1/8`) застосовуються миттєво і без мережі; хмарна відповідь приходить ≤ 20 с, інакше — повідомлення «AI did not answer in time» і Retry | Airplane mode → `reverb off` (застосовано); з мережею — E2/E4 з секундоміром або часом з Logcat (`HybridSource`) |
| K-3 | **Збій і відновлення.** Без мережі складна команда дає повідомлення «No connection…» з Retry, параметри не змінюються, спінер зникає; після увімкнення мережі Retry дає результат **без перезапуску** застосунку | Airplane mode → `make sound warmer` → перевірити повідомлення й EQ → вимкнути Airplane mode → Retry |
| K-4 | **Немає придатного результату.** Запит не про звук (`яка погода?`) або вже виконана дія (`reverb off`, коли reverb вимкнений) → чесне повідомлення «нічого не змінено», параметри без змін, застосунок не падає; значення поза діапазоном обрізаються з попередженням | Надіслати обидва запити, переглянути Studio; межові значення — unit-тести `ActionClamp` |
| K-5 | **Подальша дія.** Після Save і повторного Load зі списку збережених параметри, змінені AI, відновлюються | Після K-1 → Save → на Studio вимкнути Reverb → Library → Load → перемикач Reverb знову увімкнений; у чаті `зменш reverb наполовину` показує «було» ≈ 13% (тобто mix відновлено з запису) |

## 3. Що не входить у сценарій

- Генерація звуку моделлю і аналіз аудіо — AI керує лише параметрами ефектів.
- Власний backend і хмарне збереження записів (Firebase Auth / Firestore / Storage) — не реалізовано.
- Повна робота офлайн: без мережі працюють лише прості команди правилами.
