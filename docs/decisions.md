# Технічні рішення

Формат: рішення, причина, наслідки.

## D-01: Kotlin + Jetpack Compose
Сучасний стандарт Android, мінімум коду для інтерфейсу з нестандартним малюванням (осцилограф). Наслідок: потрібна Android Studio з підтримкою Compose.

## D-02: DSP на чистому Kotlin для POC, Oboe пізніше
Швидко перевірити ідею без налаштування NDK. Наслідок: підвищена затримка і ризик пауз GC, тому перенесення на C++ (Oboe) заплановане (R-25).

## D-03: Аудіоформат mono, 44.1 кГц, float
Спрощує DSP і малювання сигналу. Наслідок: немає стерео та панорами (L-05).

## D-04: AI повертає JSON-дії, а не керує звуком напряму
Надійно, перевіряється та однаково виконується з будь-якого джерела (правила, хмара). Наслідок: набір дій обмежений схемою в `Ai.SYSTEM`.

## D-05: Інтерфейс `CommandSource` і гібридне джерело
Незалежність від постачальника AI; правила працюють офлайн, безкоштовно й миттєво, а хмара лише для нерозпізнаних фраз. Наслідок: два способи розбору команд, які треба підтримувати узгодженими.

## D-06: Firebase AI Logic (Gemini) замість Claude API
Власник проєкту вирішив не використовувати Claude API. Firebase AI Logic не вимагає зберігати ключ моделі в додатку й інтегрується з App Check. Наслідок: потрібен налаштований Firebase-проєкт; Claude API з коду прибрано.

## D-07: Firebase замість власного backend на першому етапі
Authentication, Firestore і Cloud Storage закривають акаунти, метадані та файли без написання сервера. Аудіо зберігається в Storage, а не в Firestore (ліміт документа). Наслідок: власний REST API відкладено (api-contract.md, розділ 3).

## D-08: Ледача ініціалізація Firebase-моделі (`by lazy`)
Додаток раніше падав при старті без `google-services.json`. Тепер Firebase зачіпається лише при першому хмарному виклику.

## D-09: Master volume застосовується після ефектів, осцилограф показує вже змінений сигнал
Користувач чує і бачить одне й те саме. `View gain` осцилографа змінює лише відображення. Окремо від цього працює слайдер Volume у дБ.

## D-10: Єдиний «транспорт» семплера (курсор, loop A-B)
Замість кількох накладених голосів один відтворюваний голос із позицією, loop-маркерами та прив'язкою до сітки BPM. Простіше для редагування фрагмента; семпл не транспонується.

## D-11: Лінійна вертикальна вісь осцилографа
Логарифмічний (дБ) режим прибрано на прохання користувача: рівні відображаються окремо як Peak/RMS у dBFS і лініями сітки.

## D-12: Кільцевий буфер для Live-осцилографа з вирівнюванням по нулю
Стабільна картинка без блокувань між аудіо- та UI-потоками; ціна: вікно до 4096 семплів (~93 мс).

## D-13: Документація в `docs/` у корені репозиторію, діаграми Mermaid
Діаграми живуть поруч із кодом і рендеряться на GitHub.

## Відкрите рішення
